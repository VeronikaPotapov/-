# Личный кабинет РП

Локальный MVP-прототип продукта «Личный кабинет РП: операционный навигатор проекта».

Приложение превращает операционный план руководителя проекта в рабочий кабинет: показывает актуальные действия по проекту, позволяет отмечать выполнение, видеть прогресс и управлять участниками на уровне простой MVP-модели.

## Как запустить

Откройте файл `index.html` в браузере.

Сервер, сборщик и база данных не нужны. Данные сохраняются в `localStorage` текущего браузера.

## Основной сценарий MVP

1. Открыть приложение и нажать «Открыть демо-проект».
2. Открыть вкладку «Сейчас» и посмотреть актуальные действия.
3. Перейти во вкладки «На этой неделе» и «В этом месяце».
4. Отметить одно из действий выполненным.
5. Увидеть, что прогресс проекта обновился автоматически.

## Что реализовано

- профиль пользователя с полями «Фамилия», «Имя» и «Роль»;
- создание проекта только после заполнения профиля;
- создатель проекта автоматически становится участником с правом «Редактор»;
- доступ к проекту определяется через список участников проекта;
- проекты в списке «Мои проекты» показываются только текущему пользователю;
- переключателя «Редактор / Наблюдатель» больше нет;
- приветственный экран первого запуска;
- создание демо-проекта для быстрой проверки MVP;
- очистка локальных данных;
- карточка проекта со стадией, датами, KPI и прогрессом;
- редактирование карточки проекта для редактора;
- библиотека шаблонных операционных действий;
- отдельные статусы выполнения действий для каждого проекта;
- карточка действия работает как мини-инструкция для РП: показывает триггер, что сделать, критерий хорошего результата, подсказки, статус и комментарий;
- вкладки: «Сейчас», «На этой неделе», «В этом месяце», «На стадии проекта», «Все действия»;
- фильтры во вкладке «Все действия»;
- управление участниками и правами доступа.

## Ограничения MVP

- нет сервера;
- нет настоящей авторизации;
- нет базы данных;
- нет интеграций с ЦУП, СЭД, Outlook или Telegram;
- нет реальных уведомлений;
- `first_workday` считается как начало месяца;
- `biweekly` показывается в недельном разделе без расчета четности недели;
- библиотека действий пока задана прямо в `app.js`;
- доступ имитируется локально через имя текущего профиля и список участников проекта.

## Что можно развивать дальше

- добавить устойчивую идентификацию пользователей по email;
- добавить полноценную библиотеку операционного плана;
- вынести действия в отдельный JSON;
- добавить импорт/экспорт данных;
- добавить настоящую авторизацию и серверное хранение;
- добавить интеграции с ЦУП и календарем;
- сделать уведомления и напоминания.
